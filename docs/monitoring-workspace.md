# Network Pulse — 品牌监控首页

入口：`http://192.168.20.169:8080/monitor?lang=zh`；英文使用 `lang=en`。
这是独立的 AIOps 页面，不嵌入 Grafana。OPS Tools 顶部及四个原 Grafana 看板
都有入口；专业看板与运行简报保留。Grafana 链接使用当前主机的 3000 端口。

## 展示与交互

- 深色品牌导航、健康评分环、资源条形图、交互式历史趋势与设备分组。
- 站点、设备筛选；趋势支持 1h / 6h / 24h / 7d / 30d；条件保存到 URL。
- 中英文、全屏、手动刷新及可关闭的 60 秒自动刷新。后台标签暂停自动请求。
- 具体设备的采集异常、真实未处理无主漂移和最近备份失败；漂移和备份可跳转详情。
- 设备按厂商、交换机 / 防火墙分类。防火墙显示会话、吞吐、会话建立速率及在线时长。
- 接口放在最后，支持搜索、分页及管理开启 / 运行关闭筛选。

## 数据口径

`GET /api/monitor?site=lab&device=all&period=24h` 只读取现有采集状态、健康模型及
Prometheus。当前卡片/表格和历史趋势的时间语义分别显示：时间选择仅影响趋势，
卡片是最新观察，**不是所选时段可用率或 SLA**。

- 沿用 health v1，设备等权；同时显示覆盖率、已观察扣分、缺证未获得分数。
- “采集失败”不宣称设备物理离线。认证失败等只显示有限类别，不返回原始错误或凭据。
- Prometheus 不可用、Agent 抓取失败或数据缺失时不沿用绿色旧值。当前设备数据超过
  `AIOPS_TOPOLOGY_TTL_SECONDS`（默认 600 秒）记未知。可选字段本轮未解析到、
  或对应数据集失败时不使用导出器保留的旧值。
- 历史曲线沿用 Prometheus 样本并以 Agent `up` / 采集成功指标过滤；没有样本保持
  缺口。历史没有额外的每字段原始观察时效序列，不能据曲线证明每条采集命令持续成功。
- 流量趋势为每时点最高单接口 RX / TX；最高接口可能切换，不累加为业务总吞吐。
  PA 独立流量指标优先，按设备/接口去重；不把物理、聚合、逻辑口相加。
- TCAM 只展示 0–100% 的值，Telemetry 同资源优先，CLI 补充；不修改采集方式。
- 漂移仅统计 `origin=observed,status=open,unowned=true`，排除演练；配置库不可用显示未知。
  备份失败依据最近已有记录，并同时显示有记录设备数，未备份不伪装成备份成功。
- BGP 按设备/邻居/VRF 去重。协议卡片表示正常 / 已观察邻居，不证明未配置邻居正常。

## 实现与运行

`monitoring.py` 是有界的只读数据层，`monitoring.html` 是无外部依赖的页面。
无需新增数据库、设备连接、采集任务或 Python 依赖。

Prometheus 默认 `http://prometheus:9090`，可由部署环境变量 `AIOPS_PROMETHEUS_URL`
覆盖。浏览器不接受任意 PromQL 或目标 URL；查询模板固定、范围限制 30 天、每条
趋势约 241 点。每请求并行 3 个读查询，最多 2 组，单查询超时 8 秒，响应限制 8 MB；
成功结果缓存 25 秒、最多 24 个键。失败不缓存为正常结果。缓存不延长原始设备时效。

部署只重建 Agent，原 Prometheus / Grafana / Nautobot 继续运行。部署前保存源文件、
Agent 镜像及配置历史一致性副本和拓扑布局；回退恢复旧源码/镜像并移除新增入口即可。

## 验证

- 自动检查：无数据与零值区分、Agent 不可用、陈旧采集、可选字段旧值过滤、漂移
  排除演练、配置库不可用、PA 流量覆盖、TCAM 越界、历史缺口、查询转义与范围限制、
  缓存隔离、API 只读和设备范围校验；同时运行既有路径与健康评分回归。
- 浏览器检查：桌面/手机，中英文，范围与资源切换，搜索，图表键盘操作，缺证/失败
  后清空与恢复，以及只发出 GET 请求。
- 实际设备范围验收只使用 lab 的已有指标与采集结果，不主动登录设备。其它站点仅
  展示正常后台采集已经产生的数据；不修复、重试或修改已知认证失败设备。
